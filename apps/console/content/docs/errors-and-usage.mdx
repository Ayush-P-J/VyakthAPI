## Errors

Every error has the same form. `details` appears only when there's more to say.

```json
{ "error": { "code": "insufficient_scope", "message": "This API key does not have the \"write\" scope." } }
```

| Status | Code | What to do |
|---|---|---|
| 400 | `invalid_request` | Fix the fields listed in `details`. |
| 400 | `idempotency_key_required` | Send an `Idempotency-Key` header. |
| 400 | `invalid_cursor` | Start again without the cursor. |
| 401 | `unauthorized` | Send a valid key as `Authorization: Bearer <key>`. |
| 403 | `insufficient_scope` | Use a key with the scope this call needs. |
| 403 | `connection_revoked` | Ask the customer to connect again. |
| 405 | `dataset_not_writable` | This dataset doesn't accept writes yet. |
| 409 | `connection_not_active` | The connection isn't active. Check its status. |
| 409 | `idempotency_conflict` | Use a new key for a different request. |
| 422 | `validation_failed` | Fix the entry, using the issues in `details`. |
| 422 | `invalid_expression`, `invalid_field` | Correct the custom mapping against the existing dataset. |
| 413 | `payload_too_large` | Reduce the request body; normal JSON API requests allow 1 MB. |
| 502 | `connector_error`, `tally_error` | Inspect the connector response/logs. |
| 503 | `tally_unavailable` | Bring the connector/Tally online, or use synced reads. |
| 504 | `live_timeout` | Reduce the live range and check Tally performance. |

## Scopes

| Scope | Allows |
|---|---|
| `read` | Reading data, jobs, webhooks and usage. |
| `write` | Posting and changing entries. Needs `read` as well in the console. |
| `admin` | Connect links, webhooks, revoking connections and mapping fields. |

Scopes are independent: `admin` does not imply `read` or `write`. The `raw` scope exists in internal types but there is no public raw-response endpoint. Console sessions, device secrets and connect tokens are separate credentials.

## Usage

Implemented metered operations count by how much work they take:

| Kind | Units |
|---|---|
| Synced read | 1 |
| Live read | 5 |
| Write | 10 |

See it in the console under **Usage**, or from the API:

```sh
curl "$API/v1/usage?from=2026-11-01T00:00:00Z" -H "authorization: Bearer $KEY"
```

Dataset synced reads cost 1 unit, live reads/discovery/live validation cost 5, and a newly accepted write job costs 10. Replaying an existing idempotent job does not add another write charge. Management/status/schema/webhook-log calls are not metered by the current implementation. These are usage units; no payments are collected and prices remain placeholders. See [Pricing](/pricing).

`GET /v1/usage` returns `{data,activeConnections}` grouped by connection and kind. `from` is an inclusive timestamp and `to` is exclusive; omitted bounds use the database's current month start and now (plus one second). Console monthly reports use India time, so pass explicit timestamp bounds when comparing the two.
