## Errors

Every error has the same form. `details` appears only when there's more to say.

```json
{ "error": { "code": "insufficient_scope", "message": "This API key does not have the \"write\" scope." } }
```

| Status | Code | What to do |
|---|---|---|
| 400 | `invalid_request` | Fix the fields listed in `details`. |
| 400 | `idempotency_key_required` | Send an `Idempotency-Key` header. |
| 400 | `invalid_cursor` | Start again without the cursor. |
| 401 | `unauthorized` | Send a valid key as `Authorization: Bearer <key>`. |
| 403 | `insufficient_scope` | Use a key with the scope this call needs. |
| 403 | `connection_revoked` | Ask the customer to connect again. |
| 405 | `dataset_not_writable` | This dataset doesn't accept writes yet. |
| 409 | `connection_not_active` | The connection isn't active. Check its status. |
| 409 | `idempotency_conflict` | Use a new key for a different request. |
| 422 | `validation_failed` | Fix the entry, using the issues in `details`. |

## Scopes

| Scope | Allows |
|---|---|
| `read` | Reading data, jobs, webhooks and usage. |
| `write` | Posting and changing entries. Needs `read` as well in the console. |
| `admin` | Connect links, webhooks, revoking connections and mapping fields. |

## Usage

Each call counts towards your usage, by how much work it takes:

| Kind | Units |
|---|---|
| Synced read | 1 |
| Live read | 5 |
| Write | 10 |

See it in the console under **Usage**, or from the API:

```sh
curl "$API/v1/usage?from=2026-11-01T00:00:00Z" -H "authorization: Bearer $KEY"
```

See [Pricing](/pricing) for how usage is charged.
